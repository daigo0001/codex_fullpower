GitHub Release Lab

Issue から本番まで。どの変更を、何を根拠に、どの版として出すか。

リリースの流れ

Issue に目的と受入条件を置き、PR、検証環境、タグ・Release、本番配備まで追跡します。

ブランチ・版の戦略

公開頻度、検証期間、保守する版を踏まえて、main 中心、短期のリリースブランチ、保守ブランチを使い分けます。

Issue・PR・進捗管理

仕様や受入条件を Issue、実装と確認結果を PR、版ごとの対象と進捗を Milestone や Projects に記録します。

Git グラフで変更を追う

機能追加、旧版へのパッチ、公開後のリバートを選び、コミットと参照先を一手ずつ追います。

公開判断の演習

通常公開、緊急修正、データベース変更後の切り戻しを練習します。

資料とテンプレート

問い合わせ管理システムの記入例を読み、自分のリポジトリで使う Markdown として保存できます。
