# 基本設計書 · 社内問い合わせ管理

架空案件の記入例。対象は初回公開分。企画、業務範囲、非機能の水準は[要件定義書](requirements.md)に置く。

## 利用の流れとシステムの境界

申請者が問い合わせを作成し、窓口担当が担当を決めて対応を進める。対応を解決として記録した後、運用上の確認が済むと終了にする。問い合わせに関する作業は社内アプリが管理し、社員の有効情報は毎晩に既存システムから参照する。

~~~text
社員のブラウザー → HTTPS → Azure App Service / ASP.NET Core
      └→ Microsoft Entra ID でサインイン     └→ Private Endpoint 経由で Azure SQL
既存社員マスター → 参照 HTTPS → 定時 WebJob → ステージ検証 → Azure SQL
~~~

Web 入口と API は同じアプリに載せる。サインイン・検索・詳細・更新の権限をサーバーで評価し、社員マスターの同期ジョブは通常の画面処理から分離する。デプロイと監視の設計は[インフラ設計](infrastructure-design.md)を参照する。

### SCR-01 問い合わせ一覧

申請者は自分の問い合わせを、窓口担当と管理者は組織内の問い合わせを一覧で確認します。検索は 20 件単位です。

| 項目 ID | 項目 | 規則 | 入力と例外 | イベント |
| --- | --- | --- | --- | --- |
| L-01 | タイトル検索 | 文字列・任意。前後の空白を除去し、1〜100文字でタイトルの部分一致を検索する。 | 100文字を超えたら項目名と上限を表示する。空欄は条件なし。 | 検索を実行すると page=1 に戻す。条件はクエリに保持する。 |
| L-02 | 状態 | 新規・対応中・解決・終了から1件を選択。初期値は「すべて」。 | 定義外の値は検索 API が 400 を返す。既定値へ戻せるようにする。 | 適用ボタンで条件を送信する。 |
| L-03 | 担当者 | 選択値は employeeId。候補はラベルを業務名にし、利用者が閲覧できる問い合わせの担当者に限る。 | 担当者の指定を受けても、本人・組織の閲覧条件を必ず適用する。 | 「未割当」を指定できる。他の条件とは AND 検索。変更後は先頭ページへ。 |
| L-04 | 検索結果 | ID・タイトル・状態・更新日時を表示する。更新日時の降順、同時刻は ID 降順。 | 0件は空の理由と条件解除の案内を出す。権限内の件数だけを返す。 | 行の ID から SCR-02 に移動。戻ると検索条件とページを復元する。 |
| L-05 | ページ移動 | 1ページ20件。現在ページを読み上げ可能にし、最終ページの次ボタンを無効にする。 | データ減少でページが範囲外になれば最終ページを案内する。 | 同じ検索条件で該当ページを再取得する。 |
| L-06 | 新規登録 | 認証済みの申請者・窓口担当・管理者が本人として登録できる。 | アプリ未割当の利用者には登録リンクと API を許可しない。 | SCR-03 の新規モードに移動する。 |

| 状態 | 画面の表示 | 案内 |
| --- | --- | --- |
| 正常 | 一覧を表示 | 受付中の問い合わせを更新順に表示。検索条件と件数を確認できます。 |
| 空・初期 | 条件に合う問い合わせはありません | 条件を解除して再検索するか、新規登録へ進めます。 |
| 入力・競合 | タイトル検索は100文字以内で入力してください | 選択済みの条件を保持し、エラー項目にフォーカスします。 |
| 権限不足 | 一覧を閲覧する権限がありません | レコードと件数を表示せず、利用申請の窓口を案内します。 |
| 通信エラー | 問い合わせ一覧を読み込めませんでした | 入力済みの条件を保持します。「再読み込み」で同じ条件を試せます。 |

### SCR-02 問い合わせ詳細

本文、担当者、状態変更履歴を表示。窓口担当と管理者が、状態と担当者を変更できます。

| 項目 ID | 項目 | 規則 | 入力と例外 | イベント |
| --- | --- | --- | --- | --- |
| D-01 | 問い合わせ | 表示用受付IDとタイトル。本文と申請者は権限を確認した後に返す。 | 権限内に対象がない場合は 404 に統一し、存在の有無を区別しない。 | 一覧へ戻ると元の検索条件を引き継ぐ。 |
| D-02 | 現在の状態 | 現在値から可能な遷移先を表示する。申請者は読むだけ。 | 対応中から終了への飛び越しは 409。最新更新と競合した場合は 412。 | 「状態を更新」で API-05。読み込み時の ETag を If-Match に付ける。 |
| D-03 | 担当者 | 窓口担当・管理者のみ、同じ組織の有効な窓口担当へ割り当てる。 | 無効な担当者や対象外の組織は拒否。本人の権限が外れたら 403。 | 「割り当てる」で API-06。成功後は応答の ETag と表示を更新する。 |
| D-04 | 変更履歴 | 状態、操作した担当者、日時を更新順に表示。時刻は JST に変換する。 | 履歴0件は「状態変更はまだありません」を表示。 | 変更成功後に履歴を再取得する。履歴の読み込みに失敗しても更新結果は区別して表示する。 |
| D-05 | 編集 | 申請者本人の新規問い合わせに表示する。 | 画面表示後に対応中へ変われば、保存は競合として扱う。 | SCR-03 の編集モードへ。フォームの初期 ETag は詳細から引き継ぐ。 |

| 状態 | 画面の表示 | 案内 |
| --- | --- | --- |
| 正常 | 問い合わせの詳細 | 現在の状態と更新履歴を確認できます。 |
| 空・初期 | 状態変更はまだありません | 問い合わせ本体は表示し、履歴欄だけを空表示にします。 |
| 入力・競合 | 別の担当者が先に更新しました | 412 の場合は保存されていないことを伝え、最新の状態を確認してから判断します。 |
| 権限不足 | 問い合わせが見つかりません | 対象を読む権限がない場合も同じ 404 表示にします。読める対象の操作だけが禁止なら 403 を表示します。 |
| 通信エラー | 状態更新の結果を確認できません | 自動で再送せず、詳細を読み直して状態と履歴を照合できるようにします。 |

### SCR-03 問い合わせ登録・編集

誰が、何に困り、何を期待しているかを記録します。本人の新規問い合わせのみ編集できます。

| 項目 ID | 項目 | 規則 | 入力と例外 | イベント |
| --- | --- | --- | --- | --- |
| F-01 | タイトル | 文字列・必須。前後の空白を除去した上で 1〜100 文字。 | 空欄または101文字以上は 422。入力欄と画面先頭に同じ理由を示す。 | 登録・保存の入力値。成功前にフォームから消さない。 |
| F-02 | 問い合わせ内容 | プレーンテキスト・必須。1〜2,000文字。現在の状況と期待する結果を書く。 | 空欄・上限超過をサーバー側でも検証。表示時はテキストとして扱う。 | 入力エラー時も送信前の本文を保持する。 |
| F-03 | 新規・編集モード | 新規は状態をサーバーで新規に固定。編集では本人かつ状態が新規の条件を再確認する。 | 表示後に更新された ETag は 412。本人が操作できなくなった場合は 403。 | 編集モードの初期読み込みは API-03。最新を読み直すときは未保存の入力の扱いを確認する。 |
| F-04 | 登録・保存 | 新規は API-04、編集は API-08。新規時の操作IDは確認が済むまで保持する。 | 送信中はボタンを無効にする。応答が消えたときは登録結果の確認を案内する。 | 新規の再試行は同じ操作IDを使う。成功時は詳細へ遷移して受付IDを表示する。 |
| F-05 | 戻る | 入力変更がある状態で離れる場合は、編集を破棄するか確認する。 | 通信失敗・入力エラーの入力内容は保持する。 | 新規は SCR-01、編集は SCR-02 へ戻る。 |

| 状態 | 画面の表示 | 案内 |
| --- | --- | --- |
| 正常 | 入力内容を確認して保存 | 送信中は操作を一時停止し、成功時は詳細に移動します。 |
| 空・初期 | 新しい問い合わせ | タイトルと本文は空欄で、入力例と文字数の制限を確認できます。 |
| 入力・競合 | タイトルを入力してください | 本文を保持し、理由とタイトル欄への移動を示します。 |
| 権限不足 | この問い合わせは編集できません | 保存ボタンを無効にし、権限がある場合だけ詳細へ戻します。 |
| 通信エラー | 保存の結果を確認できません | 入力値を残し、同じ操作IDでの登録確認または編集内容の照合を案内します。 |

### SCR-04 管理者画面

社員マスター連携の結果と、ログイン中の管理者の権限を確認します。権限変更は承認済みの Entra 運用で行います。

| 項目 ID | 項目 | 規則 | 入力と例外 | イベント |
| --- | --- | --- | --- | --- |
| A-01 | 認証・権限を確認 | ログイン中の利用者にマップしたアプリロールだけを表示する。 | 管理者権限なしは管理 API で 403。機微情報のある応答本文を返さない。 | API-09 で現在の認証済みセッションの概要を取得する。 |
| A-02 | 連携日時の範囲 | 期間を JST の日付で指定。終了日は開始日以降かつ最大31日。 | 逆順や範囲超過なら理由を表示。日境界はサーバーで UTC へ変換する。 | API-07 に期間を渡して再検索する。 |
| A-03 | 連携実績 | 日時、結果、処理件数、監視用実行ID。社員の個別情報や秘密情報は画面に出さない。 | 履歴0件、実行中、成功、失敗を文言で区別する。 | 失敗の場合は実行IDと連絡先を案内する。手動再実行は初回の範囲外。 |

| 状態 | 画面の表示 | 案内 |
| --- | --- | --- |
| 正常 | 社員マスター連携は正常です | 認証済みの管理者だけが実績とアクセス概要を確認できます。 |
| 空・初期 | 指定期間に実行記録はありません | 期間を広げる操作を案内します。 |
| 入力・競合 | 開始日は終了日以前にしてください | 選択していた日付を保持し、修正する箇所を示します。 |
| 権限不足 | 管理者権限が必要です | 連携実績を読み込まず、一般機能に戻れるようにします。 |
| 通信エラー | 連携実績を取得できませんでした | 再読み込みを案内します。取得不能を連携失敗と区別します。 |

## 権限の設計

| 操作 | 申請者 | 窓口担当 | 管理者 |
| --- | --- | --- | --- |
| 閲覧、検索 | 本人の問い合わせ | 対応を許可された組織内 | 対応を許可された組織内 |
| 登録・本文編集 | 本人名義で登録、本人の新規だけ編集 | 本人名義で登録、本人の新規だけ編集 | 本人名義で登録、本人の新規だけ編集 |
| 状態と担当の変更 | 不可 | 組織内、遷移と現行版を検証 | 組織内、遷移と現行版を検証 |
| 同期実績・アクセス概要 | 不可 | 不可 | 参照のみ。権限変更は Entra の承認手順 |

画面の表示条件と API の許可条件を同じ規則でレビューする。対象の閲覧権限がなければ同じ404を返す。操作できる状態かは保存直前に再確認する。

## 設計を渡す条件

- 合意した範囲を要件 ID、画面 ID、API ID、テスト ID で辿れる。
- 一覧・詳細・登録と編集・管理者画面を、通常、空、入力不正、権限不足、通信失敗でも説明できる。
- 連携元の責任者・定時・参照範囲と、失敗時の連絡経路が合意済み。
- 状態変更の整合性を[詳細設計](detailed-design.md)と[試験仕様](test-plan.md)に引き継ぐ。
