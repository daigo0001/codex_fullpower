# 実装構成

## 画面とデータ

`index.html` には00〜12章のアンカー、目次と概要がある。`curriculum.js` が章と前提関係を定義し、`app.js` がハッシュに対応する表示と入力を制御する。章の演習は `requirements.js`、`design.js`、`azure.js`、`planning.js`、`practice.js` に配置している。相対パスで読み込むクラシックスクリプトなので `file://` でも利用できる。

`plan-model.js` は WBS、日付・依存関係、工数・人員、スケジュール計算と CSV 生成を担当する。`workspace.js` は全体バックアップのバージョンと章 ID を確認し、各章と計画の検証関数にデータを渡す。復元は全項目の検証と置き換え確認が終わってから反映する。問い合わせ管理と会議室予約の計画は別々に保持する。

ユーザーの入力は DOM のテキストやフォーム値に設定する。ZIP 解凍や外部コードの実行を伴う入力はない。CSV は UTF-8 BOM とエスケープを使い、数式として扱われ得る入力の先頭を保護する。ローカル保存に失敗した場合は同じタブのメモリーに保持し、JSON で移せる。

## 計画モデルの前提

- 8時間を1人日とし、営業日は土日と指定の休日を除く。担当者ごとの稼働率と休みを作業可能時間に反映する。
- 前提タスクが終わった後の営業日から着手する。日程を明示したタスクは内容を変更せず、重複や非稼働日に警告を出す。担当者の作業を自動で平準化する機能は含まない。
- クリティカルパスは論理依存と営業日換算の期間で計算し、人員制約によるずれはガントチャートの負荷と合わせて判断する。
- 三点見積は `(楽観 + 4 × 最頻 + 悲観) / 6`。入力は時間、結果には人日を併記する。待機や予備期間を経過日数として別に扱う。

## 配布

`npm run build:pl-lab` で CSS、JavaScript、favicon を `standalone.html` に埋め込む。生成物は同じアプリから保存できる。Markdown と JSON の参照資料は通常版の同じフォルダに置く。
